# 音声会話（往復ループ）

Claude の返答を読み上げ、ユーザーの声を聞き取って、会話をループで続ける。

## 前提の確認（最初に1回）

`claude-talk` MCP の 2 ツールが使える必要がある:
- `speak` … テキストを読み上げる（完了まで待つ）
- `listen` … マイクの発話を認識してテキストで返す

これらが見当たらない、または最初の呼び出しがエラー（`isError`）を返す場合は、**ループに入らず**にエラー文を短く伝えて止める。よくある原因:
- MCP が未登録 → `claude mcp list` に `claude-talk` が無い（リポの `scripts/install.sh` で登録する）
- マイクの許可が無い → システム設定 > プライバシーとセキュリティ > マイク で、Claude Code を動かしているアプリ（ターミナル・iTerm2 など）を ON にする
- 音声認識・読み上げのサーバーが立たない → `~/.claude-talk-mcp/direct/serve.log` / `tts-serve-qwen.log` を見る（リポの `scripts/check.py` で音を出さずに確かめられる）
- `mode` が `app` で、メニューバーの音声アプリが起動していない → `~/.claude-talk-mcp/mode` を `direct` にする

## 会話ループ

1. **読み上げる** — 今の返答を `speak` で読み上げる。読み上げ用に整形してから渡す（下記「話し言葉の作法」）。返答の最後に「どうぞ」「お願いします」などの**ターンを渡す合図は付けない**（合図があると自然な会話にならない）。人どうしの会話と同じく、話し終えたら自然に相手の番になる。
   - **割り込み**: 読み上げ中にユーザーが話すと `speak` は途中で止まって返る。返り値の 1 行目が `interrupted` のときは、2 行目以降に「読み上げた所: 「…」 (n/m 文字、s 秒)」が付く。続きを読み直さず、余計な `speak` を挟まずに**すぐ `listen`** を呼ぶ（割り込んだ発話は頭から返ってくる）。ユーザーに聞こえたのは読み上げた所までだという前提で、その新しい発話に答える（必要なら言いかけた要点を短く言い直す）。1 行目が `done` / `stopped` のときは今までどおり。
   - `interrupted` のあとの `listen` が空なら、自分の声で誤って止まった可能性が高い。「聞こえませんでした」とは言わず、言いかけた続きを短く言い直す。
2. **聞き取る** — 読み上げのあと、**余計な発話を挟まず即** `listen` を呼ぶ（`locale` 既定 `ja-JP`、`timeout` 既定 30 秒）。読み上げ完了直後からマイクを先回りで回している（プリロール）ので、読み上げの直後にユーザーが話し始めても頭から録れる。`listen` 発行までの間に話されても取りこぼさない。
3. **無音・空結果のとき** — `listen` が空文字を返したら、「聞こえませんでした。もう一度お願いします」と短く `speak` して、もう一度 `listen`。これを最大 2 回まで。それでも空なら「音声を切ります。続けるときは /voice と言ってください」と読み上げてループを終える。
4. **応答して繰り返す** — 認識テキストをユーザーの次の発言として扱い、返答を作り、1 に戻る。
5. **終了条件** — ユーザーが「終わり」「おわり」「ストップ」「やめて」「バイバイ」「またね」等の終了語を言ったら、短い別れの言葉を `speak` してループを終える。`speak`/`listen` がエラーを返したときも、その旨を伝えて終える。

最初のターンは、短い挨拶を `speak` してから `listen` で始める（例:「はい、聞いています」）。

## 話し言葉の作法（`speak` に渡すテキスト）

耳で聞いて分かる文章にする。読み上げ前に必ず整形する:

- 短い文で、1 ターン 1 論点。長い説明は要点だけに絞る。
- Markdown・コードブロック・URL・箇条書き記号・絵文字は**読み上げない**。必要なら言葉に言い換える（「ハイフン」「スラッシュ」等）。
- 記号や英略語は読みやすく（例: `~/.claude` → 「ホーム直下のドットクロード」）。
- コードやコマンドそのものは音声に向かない。「詳細は画面に出しますね」と言い、本文はテキストでも表示する。

## 画面表示との併用

音声はあくまで会話のチャンネル。認識したユーザーの発話と自分の返答は、通常どおりテキストでも簡潔に出しておくと、聞き逃しても追える。長い成果物（コード・表・手順）は読み上げず、画面に出して口頭では要約する。

## 補足

- `listen` の確定は「無音」または `timeout` 到達（direct モードでは `settings.json` の `silenceMs`、既定 0.5 秒）。ユーザーが話し終えたら自然に確定する。
- **プリロール**：`speak` 完了直後からアプリがマイクを回し始め、次の `listen` がその音声を引き継ぐ。だから「読み上げ → 即 listen」で頭が切れない。listen が来ないと約 6 秒で自動停止。
- **読み上げ中もマイクを聞いている**（エコー除去つき）。話せば読み上げが止まる。割り込みを切るときは `~/.claude-talk-mcp/direct/settings.json` に `{"bargeIn": {"enabled": false}}`。
- 明示的に速度や声を変えたい要望があれば `speak` の `rate` / `voice` を使う（未指定はシステム既定）。
